## duet 에 이미 있는 것
세션 이어가기(21.3), 구조화 리뷰 JSON, 구독 한도 감지·대기(25.1), 호출별 토큰·비용, 권한 수준(33.5), 원자적 파일 쓰기, 실행 기록·대시보드, mock 어댑터·가짜 CLI 테스트, 벤치마크.

## 가져오지 않을 것
- tmux·PTY·화면 긁기로 대화형 TUI 를 조종하는 방식(OpenRig·herdr·Orca 기본): 깨지기 쉽고 윈도우에서 어렵다. duet 의 헤드리스 `claude -p`·`codex exec` + JSON 이 더 튼튼하다.
- Electron·상주 데몬·SQLite 마이그레이션·모바일 앱·클라우드 중계: 표준 라이브러리 CLI + 로컬 웹 UI 에 과하다.
- 30종 에이전트 지원, 원격 머신 묶기, 플러그인 마켓, 계정 바꿔치기, 사용자 설정 파일(~/.claude 등)에 훅 설치: 범위 밖이거나 위험하다. 호출마다 붙이는 인자로 해결한다.
- 대화형 세션의 자동 압축·장기 연속성: duet 의 단계는 짧다.

## 벤치마크 결론과의 연결 (34·35장)
명확한 과제에서는 두 모델 협업이 정확도를 높이지 못했다. 그래서 '완제품'의 가치는 정확도보다 **사람의 시간을 아끼는 운영 경험**(주의 모델·실시간 상태·알림·줄 코멘트·정직한 비용)과 **싸고 빠른 기본 흐름**(혼자 구현 + 짧은 리뷰, 비싼 토론은 필요할 때만)에서 나온다. 경쟁 초안(E)은 정확도를 실제로 올릴 수 있는 유일한 후보라 벤치마크로 따로 잰다.

결론: **모든 면에서 앞선 도구는 없다.** 포크는 한 개만 할 수 있으므로, 여러 도구의 장점을 합치려면 duet 자체 앱이 각 도구의 설계를 다시 짜야 한다(MIT·Apache 는 출처 표기로 작은 모듈 차용 가능, NotchCrew 는 불가).
